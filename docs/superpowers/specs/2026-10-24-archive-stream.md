# SSH 归档的有界正文传输

当前本地合成基线：64 MiB 文件、四事务并发、等大历史文件时，Ruby 自身峰值中位数 1163.6 MiB，单个 Python 工作进程 460.9 MiB。Client/worker 的完整文件、base64、JSON 缓冲重叠。优化目标是在原文件上限与并发下，使正文内存与文件大小解耦，并保留全部归档事务证据。

## 职责

- Archive::Client 决定上传、服务器核验、本地提交和清理的业务顺序，拥有子进程和管道生命周期。
- 新增内部 Archive::Protocol，仅借用 input/output，维护单事务的帧缓冲、截止时间和正文分界；不得共享跨事务缓冲或关闭管道。
- Storage::AtomicFile 继续唯一拥有私有临时文件、文件同步、原子替换、目录同步及可信 Receipt。新增 `write_stream(path) { |file| ... }`，既有 `write(path, contents)` 直接复用它，不复制提交实现。
- Python worker 用 64 KiB 片段读取、复制、摘要和传输；固定目录、普通文件、读前/读后/路径身份检查、目标锁和归档不覆盖规则不变。

## 私有协议

1. 请求与阶段响应仍为单行 JSON；控制帧最多 16384 字节（含换行），读取片段最多 65536 字节。拒绝无换行超限帧、错误阶段、非对象、错误标记、EOF。
2. ready → verify → archived 元数据（bytes、sha256、archive_path）→ 恰好 bytes 个原始二进制字节 → delivered 控制帧 → cleanup/abort → complete。
3. bytes 必须为 1..67108864 的整数，sha256 必须为 64 个小写十六进制字符；正文不使用 base64，不做文本编码转换。元数据与正文、正文与 delivered 可以在同一次读中出现。
4. 每个控制阶段沿用 280 秒绝对期限；archived 元数据、整个正文及 delivered 共用一个期限，收到片段不能延长它。设备上传时间不消耗下一个 verify 阶段的读取期限。
5. worker 只有在归档读回验证后发送 archived，并在流式交付末尾再次核对身份、大小、摘要和目录/锁边界后发送 delivered。Client 完成长度、SHA256、delivered 校验后才形成 server_verified，并允许本地原子替换。
6. 只有本地保存、读回核验成功后发送 cleanup；worker 再确认 staging 的身份和摘要，删除并同步目录。任何失败不重放设备上传。
7. Client 和随调用投送的 worker 一起更新，不保留旧私有 base64 协议。

## 失败与完成事实

- 截断、额外正文、错误摘要、错误阶段及超限不得替换既有本地文件或删除 staging；远端已写归档保留。
- 本地准备、临时文件创建或中途写盘失败后，仍以有界读取完成正文校验（失败写入不再重试），尽可能保留 server_verified；本地失败仍返回 reported_with_error，发送 abort，不发送 cleanup。
- 原子替换后 fsync/收尾失败按现有可信 Receipt 保留 local_path；不得把已提交文件报告为未保存。
- 取消和非局部退出释放临时文件及进程；普通清理错误不得覆盖主失败。协议对象只借用 IO。
- Python 所有文件读取保持 MAX_BYTES 和身份检查；旧文件即使为空也须保留。新文件仍必须非空、区别于旧基线且不早于上传边界。

## 范围与验收

Ruby 3.4+，不新增运行时依赖；lib 方法注释中文、业务字符串英文。保留现有 WIP、KnownHosts 修复和回执变更，不提交、推送或发布。

测试覆盖原子流式成功/失败/取消、任意片段边界、合并读、恶意长度/帧、截断/额外字节、摘要/阶段不符、写入与持久化失败、worker 文件替换/上限、历史保留和并发锁。先 RED 后 GREEN，完整 CI、普通入口与安装探针、打包字节验证、一轮独立审查通过。

性能复用 0.25/8/64 MiB、1/4 并发、历史有无的五个负载，各三次新进程，验证业务产物；记录 Ruby/Python 自身 getrusage、耗时与分配量。代码不保存完整正文；实测必须显示大文件内存显著下降且大小增长不带来原先线性放大。合成数据不外推 SSH 网络、实机性能或各进程同时系统峰值。
