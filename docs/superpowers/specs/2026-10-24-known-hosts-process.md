# SSH 信任快照的进程所有权

`KnownHosts` 创建私有快照并在认证后合并共享信任；文件描述符可由 fork 继承，但快照的提交与删除责任属于创建进程。现有实测中，子进程 close 删除父进程快照及 `.old`，父进程的描述符仍打开；Tempfile 的 finalizer PID 检查不能保护显式 close!。

## 契约

- 创建进程记录快照所有权；只有该进程能够 commit，包含没有新增条目的情况。子进程 commit 在读取快照、取锁或写共享文件之前抛出 `ConnectionError`，code 为 `known_hosts_inherited`、phase 为 `login`，不携带 cause 或文件正文。
- 子进程 close 只关闭继承描述符，保留父进程快照及 `.old`；重复关闭安全。父进程仍可认证、提交及删除自己的文件。
- 子进程重新打开 Ssh 时先关闭继承资源，再建立属于子进程的新快照和 PTY；父进程会话仍可使用。新快照可以正常提交。
- 关闭失败时保留未完成资源的所有者；后续 close/open 重试，不遗失描述符或临时文件。原始故障优先于清理故障与延迟取消。
- 复用 KnownHosts、Ssh 和现有 Tempfile，不新增资源框架、兼容分支或公开方法。
- Ruby 3.4+；lib 方法注释中文，业务字面量英文；只为行为回归修改测试，不批量翻译测试或说明。
- 保留全部既有 WIP；不提交、推送或发布。实际 checkout、隔离安装及本地 fork/PTY 分开验证，不声称远程 SSH 实机证据。

## 验收

真实 fork 覆盖继承关闭、提交拒绝、独立重新打开；失败注入覆盖关闭重试。既有取消、错误优先级、锁竞争、替换及原子存储测试继续通过。完整 script/ci、候选包全部文件字节核对、普通/Bundler 安装后 fork 探针通过；独立审查单独记录。
